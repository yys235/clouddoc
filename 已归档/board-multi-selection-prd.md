# CloudDoc 画板框选与多选编辑改进 PRD

## 文档信息

- 文档名称：CloudDoc 画板框选与多选编辑改进 PRD
- 对标来源：`/Volumes/ForBackUp/20260423145911_rec_.mp4`
- 当前范围：只实现视频中清晰展示的框选、多选、批量工具条、类型筛选、成组拖动，不扩展到复杂编组、对齐分布、批量样式编辑全量能力

## 1. 背景

当前 CloudDoc 画板只有单选模型：

- 只能选中单个图形或单条连接线
- 不能通过拖拽框选多个元素
- 不能对一批元素进行统一移动或批量删除
- 顶部近场工具条只针对单对象，不支持多选上下文

视频中的目标体验更接近飞书画板：

- 在选择工具下，可直接在空白画布拖出浅蓝框选区域
- 框选完成后，多个对象进入统一多选态
- 画面显示一个整体包围框，而不是每个元素各自保持完整单选控件
- 顶部出现批量工具条
- 工具条中可按元素类型查看本次多选结果，如“所有图形 / 圆角矩形 / 连线 / 分区”
- 多选后可整体拖动

## 2. 目标

本轮目标：

1. 在画板中支持鼠标拖拽框选多个元素
2. 多选后展示统一包围框与批量工具条
3. 支持按元素类型筛选当前多选集合
4. 支持拖动任一已选节点时整体移动整组选中元素
5. 保持已有单选、连接线编辑、节点编辑、保存/刷新恢复能力不回退

## 3. 非目标

本轮明确不做：

- 不做真正的“编组/解组”持久化模型
- 不做旋转、多选缩放、批量改色、批量字体样式
- 不做框选后对齐、分布、自动布局的完整功能
- 不做跨文档复制粘贴
- 不做键盘组合选择（Shift 点击追加）作为主交互

## 4. 视频拆解结论

根据视频可确认的操作逻辑：

### 4.1 框选触发

- 用户处于选择工具
- 在空白区域按下并拖动鼠标，画布出现浅蓝半透明框选矩形
- 框选过程中会动态高亮命中的元素

### 4.2 选中结果

- 框选结束后，命中元素被视为一个多选集合
- 视觉上显示一个总包围框
- 顶部出现多选批量工具条

### 4.3 批量工具条

视频中可以明确识别出：

- 类型筛选入口
- 批量操作入口
- 更多入口

其中类型筛选下拉面板会列出：

- 所有图形
- 某类具体图形
- 连线
- 分区

并显示每类在本次多选中的数量。

### 4.4 拖动行为

- 多选态下，拖动选中集合中的元素，可整体移动当前筛选后的多选集合

## 5. 方案设计

## 5.1 选择模型升级

当前状态：

- `selectedNodeId: string | null`
- `selectedConnectorId: string | null`

改造后新增：

- `selectedNodeIds: string[]`
- `selectedConnectorIds: string[]`
- `selectionMode: "single-node" | "single-connector" | "multi" | "none"`
- `selectionRect: { startX, startY, currentX, currentY } | null`
- `multiSelectionFilter: "all" | "node:<type>" | "connector"`

兼容策略：

- 保留现有 `selectedNodeId / selectedConnectorId`，作为单选快捷路径
- 当进入多选态时，两者置空，由多选集合驱动渲染
- 后续若继续演进，可统一抽象成单一 selection store，但本轮先做最小侵入改造

## 5.2 框选命中规则

本轮使用“矩形相交即命中”规则：

- 节点：节点外接矩形与框选矩形相交即可选中
- 连接线：连接线路径的外接矩形与框选矩形相交即可选中

原因：

- 比“必须完全包含”更接近白板类产品习惯
- 实现复杂度可控
- 与现有节点/连接线数据结构兼容

## 5.3 多选包围框

对当前筛选后的多选集合计算统一 bounds：

- `minX / minY / maxX / maxY`
- 仅渲染一层整体选中框
- 不渲染每个节点自己的 resize handles
- 连接线端点控件也隐藏，避免与多选态冲突

本轮不开放多选框缩放，只做可视反馈和整体拖动。

## 5.4 多选工具条

多选工具条显示在整体包围框上方居中，优先贴近顶部，不够空间则翻到下方。

本轮工具条包含：

1. 类型筛选按钮
2. 批量移动到顶层/底层按钮
3. 更多按钮

其中：

- 类型筛选：展示本次多选中各类型数量，点击后切换“当前生效子集”
- 批量层级：支持当前子集置顶、置底
- 更多：至少包含复制、删除

## 5.5 类型筛选

筛选逻辑：

- 默认 `all`
- 如果选择 `node:round_rectangle`，则当前多选激活子集只包含这类节点
- 如果选择 `connector`，则当前多选激活子集只包含连接线

视觉逻辑：

- 总包围框和整体拖动只针对当前激活子集
- 下拉菜单显示全部候选类型和数量

## 5.6 多选拖动

当当前激活子集至少包含一个节点时：

- 在任意已选节点上按下拖动，按起始快照整体平移所有激活节点
- 同时平移激活连接线的 `waypoints`
- 对于两端都挂在已选节点上的连接线，不直接写死起终点坐标，只跟随节点重算路径
- 对于被单独选中的连接线且未选中端点节点时，仅平移其 `waypoints`

简化规则：

- 多选拖动以“节点优先”为主
- 当前激活子集只有连接线时，允许拖动连接线外接框，整体偏移 `waypoints`

## 5.7 与现有单选逻辑的关系

- 点击单个节点：仍进入单选节点态
- 点击单条连接线：仍进入单选连接线态
- 点击空白：清空单选和多选
- 框选成功命中两个及以上元素：进入多选态
- 框选只命中一个元素：退化为单选该元素

## 6. UI 细节

### 6.1 框选矩形

- 边框：`#4f86ff`
- 填充：`rgba(79, 134, 255, 0.12)`
- 线宽：`1.25`

### 6.2 多选包围框

- 外框使用当前单选蓝色体系，保持一致
- 四角展示小方块锚点，仅作视觉参考，不启用缩放

### 6.3 顶部工具条

- 风格延续当前画板近场工具条
- 更紧凑，按钮高度不超过 `40px`
- 类型筛选下拉宽度约 `170-190px`

## 7. 数据与持久化

多选状态本身不持久化。

需要持久化的只有多选操作真正改动的数据：

- 节点位置 `x/y`
- 节点层级 `zIndex`
- 连接线 `waypoints`
- 删除后的节点/连接线集合

刷新后只恢复最终画板内容，不恢复临时多选态。

## 8. 实施拆分

### 阶段 A：框选基础

- 增加框选状态
- 空白区域拖拽生成框选矩形
- 根据命中结果生成节点/连接线多选集合
- 单选和多选模式切换

### 阶段 B：多选可视化

- 多选整体 bounds
- 多选包围框渲染
- 屏蔽单对象控件冲突

### 阶段 C：多选工具条

- 多选工具条定位
- 类型统计
- 类型筛选下拉
- 更多菜单

### 阶段 D：批量交互

- 多选整体拖动
- 批量删除
- 批量复制
- 批量置顶/置底

## 9. 验收标准

### 9.1 框选

- 在选择工具下，从空白处拖动可出现框选矩形
- 松手后命中 2 个及以上元素时进入多选态
- 松手后命中 1 个元素时退化为单选

### 9.2 多选显示

- 多选后显示统一包围框
- 多选时不再显示每个节点的单独 resize handles
- 多选时不再显示连接线单独端点控制点

### 9.3 类型筛选

- 工具条可打开筛选菜单
- 菜单按当前多选结果显示类型和数量
- 切换筛选项后，包围框和后续操作只作用于当前筛选子集

### 9.4 批量移动

- 多选节点可整体拖动
- 保存并刷新后位置保持正确

### 9.5 批量删除

- 多选后删除可一次删除当前激活子集
- 保存并刷新后删除结果保持正确
