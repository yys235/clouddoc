# CloudDoc 画板连接线编辑专项改进 PRD

## 1. 文档信息

- 文档名称：CloudDoc 画板连接线编辑专项改进 PRD
- 适用范围：画板文档（`board`）的连接线创建、选中、编辑与静态展示
- 参考视频：`/Volumes/ForBackUp/20260423095531_rec_.mp4`
- 抽帧目录：`/Users/yys235/projects/clouddoc/output/video-analysis-20260423095531`
- 输出目标：把当前画板中的连接线交互收敛成接近视频的“近场编辑器”体验

## 2. 背景与问题

当前 CloudDoc 画板已经具备基础连接线能力，但与视频中展示的交互还有明显差距：

- 连接线虽然可创建，但还不够像“一级可编辑对象”。
- 连接线选中后的编辑能力不够聚焦，路径编辑和样式编辑的近场感不足。
- 连接线控制点、锚点和静态态/选中态的视觉层级不够清晰。
- 连接线的路径模式较少，难以复刻视频中的多段折线和圆角折线效果。
- 工具条虽然已经存在，但还不是“连接线专用短工具条”的形态。

本 PRD 目标不是扩展全量白板，而是只围绕这段视频里明确出现的“连接线编辑器”能力做改进。

## 3. 视频操作逻辑拆解

基于抽帧分析，这段视频核心操作链路如下：

1. 用户先选中一个矩形节点。
2. 从节点底部锚点发起连接线拖拽。
3. 连接线自动尝试生成直角折线路由。
4. 连接到右侧目标节点后，连接线进入选中态。
5. 被选中的连接线显示一组路径控制点。
6. 连接线下方出现一个短白色浮动工具条。
7. 用户通过该工具条持续调整连接线的路径形态。
8. 路径从简单直角折线逐步调整为多段折线，并带有圆角过渡。
9. 终点箭头保持开启。
10. 编辑完成后，连接线退出选中态，恢复为更淡的静态展示。

## 4. 界面 UI 分析

### 4.1 视觉重点

视频里的视觉中心不是节点，而是被选中的连接线。

界面层级优先级如下：

1. 被选中的连接线与其蓝色控制点
2. 连接线专用浮动工具条
3. 源节点和目标节点
4. 点阵背景

这意味着画板在“连接线编辑模式”下，应该主动降低节点和背景的存在感，让连接线成为当前唯一焦点。

### 4.2 节点视觉

- 节点样式较克制：淡蓝填充、蓝色描边、轻圆角、几乎无阴影
- 节点被选中时显示 8 个缩放点
- 锚点是轻量小圆点，不应过重或过大

### 4.3 连接线视觉

- 未选中时：浅灰线条，存在感较低
- 选中时：蓝色高亮
- 路径中存在多个控制点
- 折线支持更柔和的圆角转折，而不是死板 90 度
- 终点箭头清晰，但不过度粗重

### 4.4 工具条视觉

- 工具条是贴近连接线的短白色悬浮条
- 单排布局，宽度短，不做面板化扩展
- 白底、圆角、轻阴影、轻分隔线
- 工具条不应遮挡连接线的关键路径
- 工具条应优先显示在线段下方，空间不足时翻到上方

## 5. 产品目标

### 5.1 本轮目标

- 将连接线升级为独立可选中的一级对象
- 提供连接线专用的近场浮动工具条
- 增加更接近视频的路由模式与转角样式
- 强化锚点吸附和路径控制点反馈
- 拉开连接线编辑态与静态态的视觉差异

### 5.2 非目标

- 不扩展多人协作
- 不引入右侧常驻属性栏
- 不引入复杂流程图模板
- 不实现连接线文本的复杂排版
- 不在本轮引入 AI 或自动布局

## 6. 用户故事

### 6.1 创建连接线

作为画板编辑者，我希望从节点锚点直接拖出连接线，并自动吸附到目标节点，这样我可以快速搭建流程关系。

### 6.2 编辑连接线路径

作为画板编辑者，我希望选中连接线后，就能直接在连线附近修改路径模式，而不用去远处找属性配置，这样我的视线不会被打断。

### 6.3 调整连线观感

作为画板编辑者，我希望把连接线从普通直角折线改成更自然的多段折线或圆角折线，让图面更接近专业流程图工具。

### 6.4 查看完成态

作为阅读者，我希望编辑完成后的连接线变回低干扰静态态，让画面清晰，不一直保持强高亮。

## 7. 详细需求

### 7.1 连接线对象化

连接线必须具备完整对象属性：

- 可单独点击选中
- 可进入专用编辑态
- 可显示独立控制点
- 可显示连接线专用工具条
- 可独立修改样式和路径
- 保存刷新后完整恢复

### 7.2 连接线状态机

连接线相关状态统一为以下四态：

#### 7.2.1 `node-selected`

- 节点被选中
- 显示节点缩放点和锚点
- 可以从任一可连接锚点开始发起连线

#### 7.2.2 `connector-creating`

- 从源节点锚点拖出一条新线
- 线尾跟随鼠标移动
- 目标节点靠近时高亮可吸附锚点
- 默认优先生成直角折线路由

#### 7.2.3 `connector-selected`

- 连接线已建立并被选中
- 线条切换为蓝色高亮
- 显示路径控制点
- 显示连接线专用浮动工具条

#### 7.2.4 `connector-idle`

- 连接线未被选中
- 恢复静态样式
- 控制点消失
- 工具条消失

### 7.3 锚点与吸附反馈

- 节点四边中点默认作为可连接锚点
- 节点被选中时展示锚点
- 连线拖拽靠近目标锚点时，锚点需有明显吸附反馈
- 吸附成功后，应记录源锚点、目标锚点
- 后续移动节点时，连接线应跟随锚点自动更新

### 7.4 连接线路由模式

本轮至少支持以下模式：

1. 直线
2. 直角折线
3. 多段折线
4. 圆角折线

说明：

- 默认创建时使用直角折线
- 连接线选中后可一键切换路由模式
- 多段折线应允许保留中间折点
- 圆角折线应在折角处应用统一圆角半径

### 7.5 路径控制点

- 连接线选中后显示路径控制点
- 起点和终点需有明确控制点
- 中间转折点或中段需可见并可拖拽
- 控制点需足够小，但在浅背景上可辨认
- 控制点拖动后，路径实时更新

### 7.6 连接线专用浮动工具条

连接线被选中后，显示独立短工具条，不复用节点工具条。

工具条首版包含：

1. 线型/线宽入口
2. 箭头入口
3. 路由模式入口
4. 圆角样式入口
5. 文本入口占位
6. 更多入口

交互要求：

- 工具条默认显示在线段附近且尽量不遮挡节点
- 优先放在连接线主体下方
- 如果下方空间不足，自动切换到上方
- 鼠标点击画布空白处后关闭
- 当连接线持续选中时，工具条保持可见

### 7.7 视觉态要求

#### 7.7.1 静态态

- 连接线颜色较浅
- 控制点和工具条不可见
- 箭头和路径结构清晰但不喧宾夺主

#### 7.7.2 选中态

- 连接线切换为高亮蓝色
- 控制点可见
- 工具条出现
- 与背景、节点形成明显焦点对比

#### 7.7.3 退出编辑态

- 点击空白区，退出编辑态
- 线条恢复静态态
- 保留已修改的路由和箭头结果

## 8. 数据模型要求

连接线建议补齐以下持久化字段：

```json
{
  "id": "connector-1",
  "sourceNodeId": "node-a",
  "sourceAnchor": "bottom",
  "targetNodeId": "node-b",
  "targetAnchor": "left",
  "routingMode": "rounded-orthogonal",
  "waypoints": [
    { "x": 120, "y": 200 },
    { "x": 120, "y": 260 },
    { "x": 240, "y": 260 }
  ],
  "style": {
    "stroke": "#5b7fd8",
    "strokeWidth": 1.5,
    "dash": "solid",
    "startMarker": "none",
    "endMarker": "arrow",
    "cornerRadius": 12
  }
}
```

要求：

- `routingMode` 区分不同路径计算模式
- `waypoints` 支持中间路径控制
- `cornerRadius` 控制圆角折线表现
- 保存刷新后必须完整恢复

## 9. 实现建议

### 9.1 渲染层

- 将连接线视为独立渲染实体
- 节点层与连接线层分开管理
- 连接线选中态覆盖层单独绘制控制点与命中区域

### 9.2 交互层

- 连接创建与连接编辑使用同一套连接线模型
- 创建完成后，默认直接进入 `connector-selected`
- 路由模式切换应立即重算路径
- 中间段拖拽优先修改 `waypoints`

### 9.3 工具条层

- 为连接线单独实现 `connector toolbar`
- 不混用节点工具条，以免按钮语义污染
- 工具条按钮只保留高频入口，其余动作放入更多菜单

## 13. 风险与注意事项

- 如果连接线仍沿用过度简化的数据结构，后续很难支持多段折线和圆角折线
- 如果继续复用节点工具条，连接线工具条会变得臃肿且语义混乱
- 如果没有明确状态机，容易再次出现“节点选中”和“连接线选中”互相打架的问题
- 中间段拖拽命中区域不能过窄，否则交互会很难用

## 14. 本次视频分析结论

这段视频体现的重点不是“白板功能很多”，而是飞书把连接线做成了一个独立、近场、低打扰的编辑系统。

CloudDoc 后续如果继续对齐这类体验，重心不应再停留在侧栏图标，而应转向连接线编辑器专项能力建设：

- 连接线对象化
- 路由模式扩展
- 路径控制点编辑
- 连接线专用工具条
- 静态态 / 编辑态分层

用户通过视频 `20260508093327.mp4` 反馈：移动圆形节点时，连接线重绘仍保留过长的竖向绕行段；按预期，当目标节点向左/上靠近时，连接线右侧竖直段应该明显缩短，而不是继续沿旧路径绕行。

问题根因：

- 单端节点移动时，逻辑会先基于旧 `waypoints` 做局部调整，目的是避免连接线跳变。
- 之后 `chooseSimplerMovedConnectorWaypoints` 会在“局部旧路径”和“当前自动路径”之间选择更合理的一条。
- 旧比较只看路径点数量：`autoPath.length < localPath.length`。
- 视频中的错误场景里，两条路径点数量接近或相同，但自动路径实际曼哈顿长度明显更短，尤其是竖向绕行段更短，因此旧逻辑错误保留了较长的旧路径。
- 另外，自动路径的首尾短段会从源节点边缘出发、进入目标节点边缘，原来的穿越节点检测把这种合法首尾连接段也算作穿越节点，导致短路径被误判不可用。

本轮修订规则：

- 对移动节点后的连接线候选路径，同时比较路径点数量和实际曼哈顿长度。
- 当自动路径不穿过节点内部，且比局部旧路径明显更短时，允许切换到自动路径。
- 判断连接线是否穿过节点时，只检查中间路径段，忽略离开源节点和进入目标节点的首尾连接短段。
- 保留前几轮的稳定性原则：如果自动路径没有明显更短，仍优先保留局部旧路径，避免轻微移动造成不必要跳变。

验证结果：

- `apps/web npm run build` 通过。
- `apps/api .venv/bin/pytest tests/test_documents_api.py -k board -q` 通过。
- Playwright 使用本机 Chrome 打开临时画板 `pytest-board-connector-shorten-*`，复现“矩形连到圆形，圆形向左/上移动”的场景。
- 修复前同脚本复现到主连接线长度从 `414.5` 增长到 `574.5`。
- 修复后主连接线在拖动中和松手后都缩短到 `114.5`，确认右侧/竖向绕行段被正确收缩。
- 验证截图：`output/playwright/board-connector-shorten-fixed.png`。

### 2026-07-15 第二十九轮形状拖动连接线稳定性与箭头边界修复

用户反馈移动画板形状时，连接线偶尔会在不同路径之间乱跳，终点箭头有时还会进入目标形状内部。

问题根因：

- 节点拖动的每一个指针移动事件都会重新比较“基于旧折点局部调整的路径”和“当前自动生成的路径”。
- 当节点经过候选路径评分的临界位置时，系统会在两条拓扑不同的路径之间反复切换，形成明显跳动。
- 没有显式持久化折点的自动连接线，在拖动开始时只记录空折点数组，后续只能每帧重新路由，无法保持拖动起点的路径骨架。
- 初始为纯水平或纯垂直的自动连接线即使计算一次路由，折点简化后仍为空，必须显式展开端点短段和中间折点才能形成可移动快照。
- 原共线折点简化没有判断线段方向，会把“先走到节点外侧、再折返到锚点”的端点保护短段删除，导致最终线段从节点内部接近锚点。
- SVG 箭头图形的尖端位于 `x=9`，但标记参考点使用 `refX=8`，箭头尖端会越过连接线终点一个标记单位，进入节点边界内部。

本轮修订规则：

- 节点开始拖动时，为所有受影响连接线建立固定折点快照；自动连接线会先展开为当前可见的自动路由折点，纯水平/纯垂直路径也会保留端点短段和中间折点骨架。
- 拖动过程中始终基于起始快照和当前位移做确定性变换，不再逐帧执行候选路径择优，保证同一拖动轨迹下路径连续。
- 两端节点同时移动时整体平移折点；只移动一端时仅调整该端相邻折点，保持中间路径骨架稳定。
- 松手后仅当连接线确实穿过源节点或目标节点内部时执行一次自动重路由；有效路径保持不变，避免松手后无意义跳变。
- 共线折点只在前后线段同方向时合并；发生方向反转时保留外侧端点短段，保证箭头始终从节点外部接近锚点。
- 箭头标记参考点调整为真实箭尖位置 `refX=9`，使箭尖严格贴合节点锚点边界，箭身保留在节点外部。
