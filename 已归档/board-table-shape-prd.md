# CloudDoc 画板表格形状完整功能 PRD

## 1. 背景

用户提供视频 `/Users/yys235/Downloads/table形状的需求.mp4`，视频展示了飞书画板中的表格形状能力：表格作为画板对象存在，具备标题行、单元格编辑、行列选中、行列尺寸调整、近场浮动工具栏和保存恢复等能力。

CloudDoc 当前画板已经支持普通图形、文本、连接线、拖拽、缩放、浮动工具栏、自动保存和结构化 board JSON。表格形状需要作为一种专门的画板节点类型接入，而不是把表格降级成普通矩形或纯文本。

## 2. 目标

V1 目标是实现一个完整可用的画板表格形状，用于在画板中表达结构化信息、字段清单、类型说明、对比矩阵、简化数据结构和流程节点属性。

核心目标：

- 用户可以从画板图形入口创建表格形状。
- 表格可以像普通画板对象一样整体选中、拖动、缩放、复制、删除、保存和恢复。
- 表格内部支持标题和单元格文本编辑。
- 表格内部支持单元格、行、列选中。
- 表格支持新增/删除行列、调整行高/列宽。
- 表格样式、内容、行列尺寸和选区操作都具备稳定的数据模型。
- 表格不支持公式、筛选、排序、跨文档引用等电子表格能力。

## 3. 非目标

V1 不做以下能力：

- 不做电子表格公式、函数、排序、筛选、冻结行列。
- 不做复杂富文本单元格，仅支持单元格纯文本和基础文字样式。
- 不做合并单元格，V1 先保持规则网格。
- 不做从 Excel / CSV 粘贴自动生成复杂表格。
- 不做多人协同冲突处理。
- 不做表格与普通云文档表格的双向转换。
- 不做表格内图片、附件、评论锚点。

## 4. 用户场景

### 4.1 系统设计字段表

用户在画板中画架构图时，需要在某个模块旁边放一个字段说明表，例如字段名、字段含义、类型。

### 4.2 方案对比表

用户在流程图或白板中插入表格，对比多个方案的优缺点、成本、风险。

### 4.3 类图/数据结构辅助说明

用户在画 UML 类图、ER 图或 API 设计图时，用表格表示属性、方法、字段类型。

### 4.4 会议白板整理

用户在白板里快速列出任务、负责人、状态，不需要完整电子表格，但需要行列结构清晰。

## 5. 功能范围

## 5.1 新增表格形状入口

### 需求

- 图形库新增 `表格` 形状。
- 表格形状图标使用九宫格/表格语义图标。
- 选择表格后进入现有图形放置模式。
- 鼠标移动到画布上时显示半透明表格预览。
- 点击画布创建表格对象。

### 默认表格

- 默认尺寸：`360 x 180`。
- 默认结构：标题行 + `3 列 x 3 行` 数据区。
- 标题默认文本：`title`。
- 默认单元格：
  - 第 1 列：`Field`
  - 第 2 列：`Field`
  - 第 3 列：`Type`

## 5.2 表格数据模型

### BoardNode 扩展

新增节点类型：

```ts
type BoardNodeType = "...existing" | "table";
```

表格节点扩展字段：

```ts
type BoardTableCell = {
  id: string;
  text: string;
  style?: {
    color?: string;
    fontSize?: number;
    fontWeight?: number;
    textAlign?: "left" | "center" | "right";
  };
};

type BoardTableColumn = {
  id: string;
  width: number;
};

type BoardTableRow = {
  id: string;
  height: number;
};

type BoardTableData = {
  title: string;
  titleHeight: number;
  columns: BoardTableColumn[];
  rows: BoardTableRow[];
  cells: BoardTableCell[][];
};

type BoardNode = {
  ...
  type: BoardNodeType;
  table?: BoardTableData;
};
```

### 数据原则

- `node.width` 等于所有列宽之和。
- `node.height` 等于 `titleHeight + rows.height` 之和。
- `columns.length` 与每行 `cells.length` 必须一致。
- `rows.length` 与 `cells.length` 必须一致。
- 保存前需要 normalize，避免列宽、行高、cells 维度不一致。

## 5.3 表格渲染

### 外观

- 表格整体为圆角极小的矩形，视觉上接近飞书画板样式。
- 外框默认浅灰，选中整体时为蓝色。
- 标题行浅灰背景，文本居中加粗。
- 数据区白色背景。
- 行列分隔线浅灰。
- 单元格文本默认左对齐，垂直居中。
- 表格整体选中时显示蓝色外框和 resize 控制点。

### 文本布局

- 单元格文本默认单行显示。
- 内容过长时先在单元格内换行。
- 如果文本高度超过单元格高度，单元格内部不溢出到外部。
- V1 行高不会因输入自动无限增长；用户可以手动拖动行高。

## 5.4 表格选中模型

### 选中层级

表格需要支持 4 种内部选中状态：

- `table`：选中整个表格。
- `title`：选中标题行。
- `cell`：选中一个单元格。
- `row`：选中一行。
- `column`：选中一列。

### 选中行为

- 点击表格边框或空白区域：选中整个表格。
- 点击标题文本区域：选中标题。
- 点击单元格：选中该单元格。
- 点击行边界附近或行控制区：选中行。
- 点击列边界附近或列控制区：选中列。
- 双击标题或单元格：进入文本编辑。
- 选中表格外其他对象：清空内部表格选区。

### 视觉

- 整表选中：蓝色外框。
- 单元格选中：当前单元格蓝色边框。
- 行选中：整行蓝色横向边框。
- 列选中：整列蓝色纵向边框。
- 行/列边界 hover：对应分隔线变蓝，并显示 resize 光标。

## 5.5 文本编辑

### 标题编辑

- 双击标题进入编辑。
- 编辑框覆盖标题区域。
- `Enter` 完成编辑。
- `Esc` 取消编辑并恢复原文本。
- 标题文本保存到 `table.title`。

### 单元格编辑

- 双击单元格进入编辑。
- 编辑框覆盖当前单元格。
- 输入文本只修改当前单元格。
- `Enter` 完成编辑。
- `Shift+Enter` 在单元格内换行。
- `Tab` 移动到右侧单元格。
- `Shift+Tab` 移动到左侧单元格。
- 最后一列按 `Tab` 时移动到下一行第一列。
- 最后一行最后一列按 `Tab` 时自动新增一行，并进入新行第一列。
- `Esc` 取消编辑。

## 5.6 行列操作

### 新增行列

支持通过浮动工具栏或更多菜单操作：

- 在上方插入行。
- 在下方插入行。
- 在左侧插入列。
- 在右侧插入列。

默认新增行：

- 高度继承当前行，最小 `32`。
- 新单元格文本为空。

默认新增列：

- 宽度继承当前列，最小 `72`。
- 新单元格文本为空。

### 删除行列

- 删除当前行。
- 删除当前列。
- 删除前必须弹出确认窗口。
- 至少保留 1 行 1 列。
- 如果只剩 1 行，删除行按钮禁用。
- 如果只剩 1 列，删除列按钮禁用。

### 清空内容

- 清空当前单元格。
- 清空当前行。
- 清空当前列。
- 清空操作需要二次确认，避免误删。

## 5.7 行高和列宽调整

### 列宽调整

- 鼠标 hover 到列分隔线附近时，显示列宽调整光标。
- 按住拖动后，只调整相邻列边界。
- 默认策略：调整左侧列宽，表格总宽度同步变化。
- 列最小宽度：`56`。
- 拖动过程中实时更新渲染。
- 松手后写入历史栈并触发自动保存。

### 行高调整

- 鼠标 hover 到行分隔线附近时，显示行高调整光标。
- 按住拖动后调整该行高度。
- 行最小高度：`28`。
- 表格总高度同步变化。
- 松手后写入历史栈并触发自动保存。

### 标题行高度

- 标题行也支持拖动调整高度。
- 标题行最小高度：`32`。

## 5.8 整体拖动和缩放

### 拖动

- 拖动表格非编辑区域时移动整个表格。
- 拖动过程中内部选区不丢失。
- 拖动完成后保存位置。

### 缩放

- 表格整体 resize 时，列宽按比例缩放。
- 行高按比例缩放。
- 最小尺寸约束：
  - 表格宽度不小于所有列最小宽度之和。
  - 表格高度不小于标题行和所有行最小高度之和。
- 缩放后写回 `node.width`、`node.height`、`columns.width`、`rows.height`、`titleHeight`。

## 5.9 工具栏

### 整表选中工具栏

保留现有形状工具栏能力：

- 填充色。
- 边框色。
- 文本颜色。
- 字号。
- 文本样式。
- 评论占位。
- 更多。
- 删除。

### 单元格选中工具栏

单元格选中时工具栏应支持：

- 文本颜色。
- 字号。
- 加粗。
- 对齐方式。
- 清空单元格。
- 插入行/列。
- 删除行/列。
- 更多。

### 行列选中工具栏

行/列选中时支持：

- 插入行/列。
- 删除行/列。
- 清空行/列内容。
- 文本样式批量应用。

### 菜单位置

- 所有表格相关菜单必须在视口范围内。
- 下方空间不足时向上展开。
- 内容过多时内部滚动。

## 5.10 快捷键

### 编辑态

- `Enter`：提交编辑。
- `Shift+Enter`：单元格内换行。
- `Esc`：取消编辑。
- `Tab`：下一个单元格。
- `Shift+Tab`：上一个单元格。

### 选中态

- `Delete` / `Backspace`：
  - 选中单元格：清空内容，需要确认。
  - 选中行/列：删除行/列，需要确认。
  - 选中整表：删除表格，需要确认。
- 方向键：在单元格之间移动选区。
- `Cmd/Ctrl+C`：复制表格或单元格文本。
- `Cmd/Ctrl+V`：粘贴文本到当前单元格。

## 5.11 历史记录与自动保存

- 表格内容编辑应进入撤销/重做历史。
- 行列新增、删除、尺寸调整应进入撤销/重做历史。
- 拖动/缩放整表应进入撤销/重做历史。
- 操作完成后复用现有自动保存机制。
- 刷新后恢复完整表格结构、内容、尺寸、样式。

## 5.12 后端校验

后端 board 校验需要接受 `type = "table"`。

校验规则：

- `table` 必须存在。
- `title` 必须是字符串。
- `titleHeight` 必须是正数，且不小于 `32`。
- `columns` 必须是非空数组。
- `rows` 必须是非空数组。
- `cells` 必须是二维数组。
- `cells.length === rows.length`。
- 每一行 `cells[row].length === columns.length`。
- 列宽最小值 `56`。
- 行高最小值 `28`。
- 单元格文本必须是字符串。
- 非法结构应返回 `400`。

## 5.13 兼容性

- 旧 board 文档没有 `table` 节点，不受影响。
- 普通 shape 的 `text` 逻辑不应被表格节点污染。
- 表格节点不参与普通节点的自动文本高度扩展逻辑。
- 表格节点可以被连接线吸附，连接点仍使用表格整体边框的四个 anchor。

## 6. 交互流程

### 创建表格

1. 用户点击图形工具。
2. 在图形面板选择 `表格`。
3. 鼠标移动到画布，出现表格半透明预览。
4. 点击画布，创建默认表格。
5. 新表格被选中，显示整表外框和浮动工具栏。

### 编辑单元格

1. 用户点击某个单元格。
2. 单元格显示蓝色选中框。
3. 用户双击单元格。
4. 单元格进入编辑状态。
5. 用户输入内容。
6. 按 `Enter` 完成编辑，自动保存。

### 调整行高

1. 用户移动到行分隔线。
2. 分隔线变蓝，鼠标变为上下 resize。
3. 按住拖动，当前行高度实时变化。
4. 松手后提交历史记录并自动保存。

### 调整列宽

1. 用户移动到列分隔线。
2. 分隔线变蓝，鼠标变为左右 resize。
3. 按住拖动，当前列宽实时变化。
4. 松手后提交历史记录并自动保存。

## 8. 技术设计建议

### 前端组件拆分

建议拆分为：

- `BoardTableShape`：负责表格 SVG/HTML 渲染。
- `BoardTableEditor`：负责标题和单元格编辑输入层。
- `BoardTableSelectionOverlay`：负责选区、行列边界 hover、resize 控制。
- `boardTableUtils.ts`：负责 normalize、插入行列、删除行列、尺寸计算。

### 渲染方案

建议优先使用 SVG 渲染表格线框和单元格文本，编辑态使用 `foreignObject` 或绝对定位 input/textarea 覆盖当前单元格。

原因：

- 当前画板主体是 SVG，表格作为画板对象更容易参与缩放、拖动、导出和连线吸附。
- 编辑态用输入层可复用现有输入行为。

### 状态设计

新增局部状态：

```ts
type TableSelection =
  | { nodeId: string; kind: "table" }
  | { nodeId: string; kind: "title" }
  | { nodeId: string; kind: "cell"; rowIndex: number; columnIndex: number }
  | { nodeId: string; kind: "row"; rowIndex: number }
  | { nodeId: string; kind: "column"; columnIndex: number };

type TableEditState =
  | { nodeId: string; kind: "title"; value: string }
  | { nodeId: string; kind: "cell"; rowIndex: number; columnIndex: number; value: string };

type TableResizeState =
  | { nodeId: string; kind: "row"; rowIndex: number; startY: number; startHeight: number }
  | { nodeId: string; kind: "column"; columnIndex: number; startX: number; startWidth: number }
  | { nodeId: string; kind: "title"; startY: number; startHeight: number };
```

## 12. 风险

- 表格内部选区会和整表拖动/缩放事件冲突，需要明确事件优先级。
- SVG 文本和编辑输入层的定位需要和 zoom/viewport 保持一致。
- 行列 resize、整体 resize、单元格编辑都需要进入现有历史栈，避免撤销行为不一致。
- 后端 JSON 校验需要保持严格，否则非法表格结构会导致前端渲染崩溃。
